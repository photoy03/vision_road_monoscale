## 바뀐 선택 규칙

1. 확인된 경계선을 차량 이동에 맞춰 현재 좌표로 옮긴 뒤 현재 후보와 비교한다. 공통 전방 구간에서 횡방향 차이의 중앙값이 0.35m 이내면 유지 가점을 준다. 최대 2점이며 거리 오차와 마지막 실측 이후 시간에 따라 감소한다.
2. 기존 차선과 다른 후보가 이기려면 유지 가점을 포함한 기존 후보 점수보다 1.5점 이상 높고, 같은 새 후보가 3프레임 이어져야 한다. 같은 프레임의 내부 재평가는 횟수를 올리지 않는다.
3. 기존 후보 자체가 없으면 새 후보 확인 중 실제 페인트를 새로 만들어내지 않는다. 기존의 짧은 예측 표시는 예측으로 구분된다. 추적 기억은 최대 0.25초이고, 등록이 끊기면 옛 좌표의 유지 가점을 쓰지 않는다.
4. 점선 조각 간 전방 공통 구간이 없으면 횡방향 변화 여부를 판단할 수 없다. 이 경우 교체 보류로 새 점선을 막지 않고 기존 관측·확인 규칙으로 넘긴다. 차선 폭을 이용한 보조 수집도 비교 가능한 구간에서는 추적 기준에서 벗어나는 후보로 우회 교체하지 못하게 했다.
5. 큰 변화 감점은 신뢰할 수 있는 이동 보정 기준이 있을 때 양방향으로 적용한다.

설정은 `src/vision_road/config/carla.yaml`의 `carla_tracking_*` 항목이다. 기존 토픽, 메시지 형식, 차선 스타일 분류를 유지한다. 실제 페인트 조각과 표시용 경계선은 계속 별도로 발행하며 중심 경로는 추가하지 않았다.

## 처리 시간 확인

첫 ROS 전체 재생은 차선·스타일·실측 마커·경계선 마커 모두 1,807개 누락 없이 약 30Hz였지만, 실측 차선 전달 지연 95백분위가 143.2ms로 설정한 100ms 기준을 넘었다. 기능을 끈 대조 실행은 77.7ms였다. 이에 후보 좌표 정렬 결과를 감점/가점 계산에서 공유하고, 고정 길이 오차의 중앙값 계산을 간소화했다. 최적화 전후 1,807프레임 모두 실측 페인트 좌표·경계선 좌표·추적 의사결정이 정확히 동일함을 확인했다. 최적화 후 ROS 재검사 결과는 `ros30hz_optimized/summary.json`을 기준으로 한다. 초기 실패 결과도 삭제하지 않고 남겼다.

재현용 스크립트의 `TRACKING_WORK_ROOT` 환경변수를 `INPUT_LOCATION.txt`에 적힌 `input`의 상위 폴더로 지정하면 같은 격리 복사본과 입력을 사용한다. 예: `python3 evaluate.py after`. 입력 캐시 약 211MiB는 원본 rosbag과 별도이며 결과 폴더에 중복 복사하지 않았다.
