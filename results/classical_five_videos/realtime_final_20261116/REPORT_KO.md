# 차선 인식부 마무리: 실시간 확인과 지연 줄이기 (계획 16)

2026-11-16–17. 문서 `docs/lane_improvement_research.md`의 "차선 인식부 마무리 계획" 절을 따랐다. 세 영상(maploop, Town05, Town04)을 녹화된 로스백에서 실제 속도(header stamp 간격, 30 Hz)로 재생했다. 검출기, 표시 필터, HERO HUD를 함께 띄웠다. 설정은 `carla.yaml` 하나이고, 영상별 설정은 없다. 학습 거르기는 기본(꺼짐)이다.

## 한 줄 요약

| 기준 | maploop | Town05 | Town04 |
|---|---|---|---|
| 처리한 프레임 비율 ≥ 99% | **100%** | **100%** | **100%** |
| 영상 발행 → 표시선(`/road/lane_display_markers`) p95 ≤ 33 ms | 43.8 ms ✗ | 43.5 ms ✗ | **31.0 ms ✓** |
| 지연이 쌓이지 않음 (마지막 10% − 처음 10%) | −1.6 ms ✓ | −0.5 ms ✓ | +5.3 ms ✓ |
| HUD 표시선 끊김 (100 ms 넘는 간격) | 0회 ✓ | 0회 ✓ | 0회 ✓ |
| 표시선이 0 m(차)부터 | 100% ✓ | 100% ✓ | 100% ✓ |
| 실시간 결과 = 오프라인 결과 | 같음 ✓ | 같음 ✓ | 같음 ✓ |

- Town04는 모든 기준을 채웠다.
- maploop과 Town05는 지연 p95만 못 채웠다.
  - 평균은 29 ms로 한 프레임 간격 안이다.
  - 33 ms를 넘는 프레임이 약 30%, 50 ms를 넘는 프레임은 0.2–0.4%다.
  - 남은 몫은 검출기 자체(파이썬, p95 24–25 ms)와 6 MB 영상 전달(약 6 ms)이다.
- 처음 상태에서는 지연이 재생 동안 계속 쌓였다. 300프레임 시험에서 p95가 382 ms였고, 재생 중 349 ms 늘었다. 지금은 쌓이지 않는다.

## 측정 방법 (`tools/realtime_eval.py`)

- `tools/replay_maploop.py`로 영상을 30 Hz로 재생한다.
  - 영상 header stamp 간격으로 보낸다.
  - `/carla/ground_truth/pose`도 함께 보내고, `reference_pose` 노드가 `/road/reference_odom`으로 바꾼다.
  - 기존 도구가 이미 header stamp 간격으로 재생하므로 `--bag`과 `--cache`만 영상별로 준다. Town04·Town05 로스백의 메시지 timestamp가 약 1093초에 걸쳐 있어도 실제 속도로 나온다.
- 같은 단조 시계(CLOCK_MONOTONIC)로 영상마다 다음 시각을 이어 붙인다.

| 시각 | 의미 | 기록하는 곳 |
|---|---|---|
| 발행 | 재생 도구가 영상을 보낸 시각 | 재생 도구 |
| 수신 | 검출 노드의 영상 콜백 | 검출 노드 성능 기록(이번에 추가) |
| 시작 | 처리 시작 | 성능 기록 |
| 계산 끝 | 검출 끝 | 성능 기록 |
| 출력 끝 | 출력 스레드 끝 | 성능 기록 |
| 경계·표시 도착 | 경계선·표시선 토픽이 도착한 시각 | 측정 프로세스 |

- 'HUD 수신'은 측정 프로세스가 HUD와 같은 토픽(`/road/lane_display_markers`)을 구독해 잰 값이다.
  - HUD 프로세스 안의 수신 시각은 HUD를 고쳐야 잴 수 있어 재지 않았다.
  - HUD는 KeepLast(1)로 구독하므로 HUD 쪽에는 지연이 쌓일 수 없다.
  - 모든 실행에서 HUD 프로세스는 끝까지 살아 있었다.
- 측정 조건:
  - 노트북 Ryzen 7 5800H(16스레드), CPU 정책 `powersave`(amd-pstate-epp). 시스템 설정은 바꾸지 않았다.
  - 화면에는 데스크톱 앱(브라우저, Claude 데스크톱 등)이 함께 돌았다.
  - 재생 도구도 같은 컴퓨터에서 zstd 압축 풀기와 체크섬을 한다.

**Town05와 maploop 지연을 기준 안으로 넣으려면**:
- 검출기 핵심을 네이티브 코드로 옮겨야 할 것으로 본다. 대상은 칠 조각 처리, 사슬 잇기, 시간 추적이다. 지금 남은 시간은 파이썬 호출 비용으로 여러 곳에 퍼져 있어, 결과를 바꾸지 않는 미세 조정으로는 1–2 ms씩밖에 줄지 않는다.
- 6 MB 영상 전달(약 6 ms)은 카메라 쪽에서 영상을 줄이거나 공유 메모리 전달을 써야 줄어든다.
- 이 두 가지는 이번 범위 밖이라 하지 않았다.

## 실행 방법

명령 하나로 검출기(표시 필터 포함) + HUD를 띄운다.

```bash
./run_lane_hud.sh town04            # Town04 녹화를 30 Hz로 재생하고 끝나면 정리
./run_lane_hud.sh town05 --loop     # 끝나면 다시 재생, Ctrl+C로 멈춤
./run_lane_hud.sh maploop --no-hud  # HUD 없이
./run_lane_hud.sh live              # 재생 없이, 살아 있는 CARLA가 보내는 영상과 위치를 받음
```

- 영상 이름: `maploop`, `town04`, `town05`, `live`.
- 옵션:
  - `--frames N`: 앞 N프레임만
  - `--learned`: 학습 거르기(GPU)
- `live` 모드에서 CARLA 쪽이 보내야 하는 것:
  - `/sensing/camera/dashcam/image_raw`: 1920×1080 bgr8/rgb8, 지금의 대시캠 보정과 같은 장착
  - `/carla/ground_truth/pose`
- 검출 설정은 `src/vision_road/config/carla.yaml` 하나다. 검출기(`vision_road`)와 표시 필터(`lane_display_filter`) 절이 모두 들어 있다.
- 재빌드 없이 소스가 바로 쓰인다(`install`이 개발 모드 링크).
- HUD(`/home/jaehun/Desktop/hero-hud-main`)는 이번에 고치지 않았다. 빌드돼 있는 것을 그대로 쓴다.
  - 다시 빌드하려면 Qt5Svg 개발 파일이 필요하다.
  - 전에 쓰던 `/tmp/hero-hud-qt`는 재부팅으로 없어졌다.
- 측정만 다시 하려면:

```bash
python3 tools/realtime_eval.py --video town05 --output OUT --launch-arg display_filter_inline:=true
```

`--record`를 붙이면 HUD와 겹쳐 그리기 화면을 녹화한다.
